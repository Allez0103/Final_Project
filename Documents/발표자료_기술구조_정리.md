## 1. 개요

PA²는 CAD 기반 조립 순서 초안을 자동으로 추천하고, 사용자가 수정·확정한 결과를 작업 안내 영상으로 제작하는 Python 기반 Windows 데스크톱 프로그램이다.

화면, 업무 처리, CAD 계산, 저장을 역할별로 분리한 모듈 구조로 구현했다.

| 계층 | 사용 기술 | 역할 |
|---|---|---|
| 사용자 인터페이스 | PySide6 / Qt | 프로젝트 관리, 순서 편집, 작업 속성 입력 |
| CAD 분석·경로 계산 | OCP / Open CASCADE | STEP 해석, 형상 분석, 접촉·간섭 검사 |
| 3D 표시·애니메이션 | VTK | 모델 표시, 부품 이동, 하이라이트, 카메라 제어 |
| 데이터 관리 | SQLAlchemy + SQLite, 파일 저장소 | 프로젝트와 CAD·순서·확정본 연결 |
| 영상 제작 | Pillow, NumPy, FFmpeg | 안내 화면 합성 및 MP4 인코딩 |

전체 처리 흐름:

> STEP 입력 → 분석·그룹화 → 분해 순서 탐색 → 조립 순서 변환 → 사용자 편집·확정 → 영상 생성

발표용 설명:

> CAD 분석부터 순서 추천, 사용자 편집, 영상 제작까지 연결하되, 각 기능은 독립된 모듈로 나누어 구현했습니다.

## 2. 기능구현

기능은 3D 도면 저장·분석, 조립 순서 자동 생성, 조립 순서 편집·확정, 영상 생성의 네 구조로 나눈다. 각 구조는 이전 단계의 데이터를 입력으로 받아 다음 단계에 전달한다.

| 구조 | 입력 | 출력 |
|---|---|---|
| 3D 도면 저장 및 분석 | 완제품·개별 부품 STEP | 부품 그룹, 정밀 형상, 접촉 관계 |
| 조립 순서 자동 생성 | 분석 결과, 기준·예외 부품 | 조립 순서 초안, 경로 판정·진단 |
| 조립 순서 편집/확정 | 자동 추천 초안 | 사용자 수정값이 반영된 확정본 |
| 영상 생성 | 사용자 확정본, 형상 데이터 | 조립 안내 MP4 |

### 2.1 3D 도면 저장 및 분석

#### 2.1.1 3D 도면 저장 구조 (DB)

##### 사용 기술

SQLite, SQLAlchemy ORM, SHA-256, JSON, BREP 캐시를 사용한다. 별도 데이터베이스 연결 설정이 없는 현재 기본 실행은 SQLite를 사용한다.

##### 구현 구조

핵심은 CAD 파일 전체를 DB에 넣는 방식이 아니라, DB의 관리 정보와 실제 파일을 연결하는 구조라는 점이다.

| 저장 대상 | 저장 방식 |
|---|---|
| 프로젝트명·차종·품종 | SQLite 테이블 |
| 입력 파일의 해시·경로·역할 | SQLite의 자산·프로젝트 자산 테이블 |
| 부품 그룹·구성 바디·접촉 관계 | 분석 스냅샷에 연결된 테이블 |
| 순서·방향·거리·주의사항 | 조립 계획과 단계별 테이블 |
| 사용자 확정본 | 확정 시점의 계획을 JSON 스냅샷으로 저장 |
| 실제 STEP·BREP·MP4 | 프로그램 관리 폴더에 파일로 저장 |

데이터와 파일의 연결 구조:

```text
프로젝트
 ├─ 입력 파일 참조 ──→ 관리 사본 STEP
 ├─ 분석 스냅샷 ────→ 부품 그룹·구성 바디·접촉 관계
 │                    └─→ 형상 BREP 캐시
 └─ 조립 순서 초안
      └─ 사용자 확정본 ──→ 해당 프로젝트의 영상 생성
```

- 프로젝트 ID, 스냅샷 ID, 부품 그룹 ID 등으로 데이터를 연결한다.
- 입력 파일은 SHA-256으로 식별하며, 같은 내용의 파일은 관리 사본을 재사용한다.
- 원본 CAD는 수정하지 않는다.
- 프로젝트를 다시 열 때 저장된 부품 구성과 형상 캐시를 복원한다.
- 캐시를 사용할 수 없으면 보관한 STEP 사본에서 재생성한다.
- 기본 작업 데이터는 `%LOCALAPPDATA%\THN\PA2`에 저장하며, 별도 데이터 경로 설정이 있으면 해당 설정이 우선한다.

##### 처리 흐름

> 프로젝트 생성 → 입력 파일 해시 계산 → 관리 사본 저장 → 프로젝트와 자산 연결 → 분석·순서·확정본 저장 → 기존 작업 복원

##### 발표용 설명

> SQLite에는 프로젝트와 파일의 관계를 저장하고, 실제 CAD와 영상은 파일 저장소에서 관리합니다. 분석 결과와 조립 순서를 동일한 프로젝트에 연결해 작업을 복원할 수 있도록 구성했습니다.

#### 2.1.2 3D 도면 분석

##### 사용 기술

Open CASCADE의 STEP Reader, BREP 형상 분석, 형상 특징 매칭, 접촉 그래프를 사용한다. OCP는 Python에서 Open CASCADE를 사용하기 위한 바인딩이다.

##### 처리 흐름

> STEP 읽기 → 단위 확인 → 솔리드 추출 → 형상 특징·유효성 분석 → 부품 파일 대조·그룹화 → 초기 접촉 관계 생성

##### 구현 구조

| 분석 항목 | 실제 구현 방식 |
|---|---|
| STEP 읽기 | `STEPControl_Reader`로 CAD 형상을 읽고 mm 기준으로 처리 |
| 바디 추출 | 완제품 형상에서 솔리드를 개별 바디로 추출 |
| 기본 형상 분석 | 체적·표면적·중심·경계상자 계산 |
| 형상 유효성 | `BRepCheck_Analyzer`로 형상 유효성 확인 |
| 부품 파일 대조 | 체적·표면적·크기와 바디 중심 간 거리 비교 |
| 그룹화 | 대응하는 바디들을 하나의 부품·이동 단위로 구성 |
| 접촉 관계 | 경계상자로 후보를 줄이고 정밀 형상 기반 접촉·거리 판정 |

자동 그룹화는 기본 기준으로 먼저 매칭한 뒤, 남은 미매칭 바디에 대해서만 완화 기준으로 재시도한다. 재시도에서는 후보가 하나이고 다른 부품 정의와 충돌하지 않을 때만 그룹화한다.

발표에서 구분할 사항:

- ‘최소 조립단위 병합’은 실제로는 부품 파일을 기준으로 여러 바디를 하나의 이동 단위로 묶는 것이다. 제조 공정을 이해해 최소 조립단위를 스스로 발견하거나 CAD 형상을 모두 하나로 합치는 방식은 아니다.
- 초기 겹침의 정밀 체적 판정과 허용 여부 판단은 주로 순서 탐색의 방향·경로 검사에서 수행한다. 불러오기 단계의 접촉 계산과 구분해야 한다.
- 자동 그룹화가 되지 않은 경우에는 순서 생성 전에 수동 그룹화로 보완할 수 있다.

##### 발표용 설명

> 완제품의 솔리드를 분석한 뒤 개별 부품 파일의 형상 특징과 대조하여 동일 부품을 구성하는 바디를 하나의 이동 단위로 그룹화했습니다.

### 2.2 조립 순서 자동 생성

#### 2.2.1 조립 순서 생성 원리

##### 사용 기술

분해 기반 역순 계획, 접촉 그래프, 노출도 휴리스틱, 제한된 백트래킹, 정밀 CAD 경로 검사, 결과 캐시, 별도 계산 프로세스를 사용한다.

##### 핵심 원리

완성된 제품에서 부품을 제거하는 분해 순서를 탐색한 뒤, 순서와 이동 방향을 반대로 바꾸어 조립 순서를 만든다.

현재 구현은 일반 부품 순서 탐색과 볼트·너트 배치를 분리한 2단계 구조다.

##### ① 일반 부품의 분해 순서 탐색

- 기준 부품은 고정한다.
- 볼트·너트를 탐색 대상과 장애물에서 제외한다.
- 남은 일반 부품 중 외부 노출도가 높은 부품을 먼저 시도한다.
- 일반 부품은 ±X·±Y·±Z의 6방향을 검사한다.
- 가장 넓은 평면 접촉면에서 멀어지는 방향을 우선하고, 초기 겹침 등이 있으면 노출도 순위를 사용한다.
- 한 방향이 통과하면 나머지 방향 검사는 생략한다.
- 제거할 수 없으면 다른 부품을 시도하고, 제한 범위 안에서 이전 선택으로 되돌아간다.
- 부품을 제거할 때마다 잔여 구성을 갱신한다.

##### ② 볼트·너트 삽입

- 접촉 그래프와 체결부 연결 관계로 관련 일반 부품을 찾는다.
- 분해 기준으로 관련 일반 부품보다 먼저 제거되도록 배치한다.
- 볼트는 머리 쪽 축 방향을 우선 사용한다.
- 체결부의 상세 이동 경로 검사는 생략한다.
- 전체 분해 순서를 뒤집으면 일반 부품을 조립한 뒤 관련 볼트·너트를 체결하는 순서가 된다.

##### ③ 반복 검사 감소와 계산 분리

같은 잔여 상태, 같은 경로, 이미 확인한 차단 근거를 재사용한다. 정밀 CAD 계산은 multiprocessing 기반 별도 프로세스에서 수행해 시간 제한과 취소를 처리한다.

##### 처리 흐름

> 기준·예외 설정 → 체결부 제외 → 일반 부품 순서 탐색 → 미해결 항목을 포함한 편집용 초안 구성 → 체결부 삽입 → 순서·방향 반전 → 조립 초안

##### 발표용 설명

> 부품 수가 많은 체결부를 정밀 탐색에서 분리하고, 일반 부품의 순서를 먼저 계산한 뒤 관련 체결부를 삽입하여 검사 부담을 줄였습니다.

##### 검증 범위와 성능 수치의 표현

‘기준 부품만 남을 때까지 간섭 없이 제거’는 탐색의 목표다. 현재는 예외 부품과 미해결 부품도 초안에 포함하므로 전체 초안 생성이 모든 경로의 간섭 검증 완료를 뜻하지는 않는다.

원본 TXT의 ‘50분 → 15분’은 다음과 같이 표현한다.

> 여러 탐색·캐시 최적화를 반영한 개발 과정에서 순서 생성 시간을 약 50분 수준에서 약 15~16분 수준으로 단축했습니다.

최근 전체 탐색 기록은 v17의 893.614초(약 14분 54초), v19의 935.932초(약 15분 36초)다. 버전별 그룹 구성·예외 조건 등이 달라 볼트·너트 분리만의 단독 개선 효과나 동일 조건 성능시험 결과로 제시하면 안 된다.

#### 2.2.2 머신러닝 적용 (미구현)

##### 현재 상태

현재 기본 추천은 기하·규칙 기반이며, 학습된 모델을 현재 GUI의 기본 추천에 적용하지 않았다.

다만 향후 적용을 위한 학습 데이터 저장, 특징 추출, 모델 학습·추론 기반 코드는 존재한다. 따라서 이 절의 ‘미구현’은 학습 기반 추천의 실제 적용이 완료되지 않았다는 의미로 구분한다.

발표용 제목을 보완한다면 ‘머신러닝 기반 후보 순위 추천 — 향후 적용’으로 표현할 수 있다.

##### 현재 알고리즘의 개선 과제

외부 노출도가 높은 부품부터 시도하는 규칙만으로는 실제 제거 가능성을 항상 먼저 판단할 수 없다. 우선 시도한 부품이 막히면 다른 후보를 검사해야 하므로, 우선순위가 부적절한 상태에서는 실패하는 검사에 시간이 사용될 수 있다.

머신러닝은 이 후보 선정 순위를 개선하는 방향으로 적용한다.

##### 기반 기술 및 향후 구조

현재 마련된 기반 기술은 LightGBM의 `LGBMRanker`, LambdaRank, 특징 추출·학습 사례 저장 모듈이다.

| 구성 | 역할 |
|---|---|
| 입력 상태 | 현재 남아 있는 부품과 접촉 관계 |
| 부품 특징 | 종류·크기·체적·위치·기준 부품과 거리·접촉 수 등 |
| 학습 정답 | 사용자가 확정한 순서에서 해당 상태의 다음 선택 부품 |
| 모델 출력 | 각 후보 부품의 우선순위 점수 |
| 후속 처리 | 점수가 높은 후보부터 기존 CAD 경로 검사 수행 |

향후 적용 흐름:

> 확정 순서 축적 → 상태별 후보·특징 생성 → 순위 모델 학습 → 다음 후보 점수 계산 → 우선순위대로 경로 검사 → 상태 갱신·반복

‘다음 부품의 확률 예측’보다 ‘다음 분해 후보의 우선순위 예측’이 현재 마련된 순위 모델과 맞는 표현이다. 순위 점수를 그대로 보정된 확률로 해석하지 않는다.

- 직전에 제거한 부품 하나만 보는 것이 아니라 현재 남은 전체 구성과 부품 관계를 반영한다.
- 전체 순서를 한 번에 생성하는 대신, 상태가 바뀔 때마다 다음 후보의 순위를 계산하는 구조로 적용한다.
- 모델은 검사 순서를 개선하는 역할이며, 간섭 검사를 대신하거나 분해 가능성을 보증하지 않는다.

##### 발표용 설명

> 향후에는 사용자 확정 사례를 학습하여 현재 조립 상태에서 다음에 분해할 후보의 우선순위를 예측하고, 불필요한 경로 검사 시도를 줄일 계획입니다.

### 2.4 영상 생성

#### 사용 기술

VTK 오프스크린 렌더링, NumPy, Pillow, FFmpeg, Qt Multimedia를 사용한다.

#### 구현 구조

영상은 화면을 녹화하는 방식이 아니라, 확정된 계획에서 프레임별 장면을 계산해 렌더링하고 인코딩하는 방식이다.

| 처리 단계 | 사용 기술·구조 |
|---|---|
| 확정본 확인 | 편집 내용과 확정본의 일치 여부 확인 |
| 시간축 구성 | 단계별 카메라 회전·점멸·이동 시간을 배정 |
| 부품 이동 | 방향·거리와 시간에 따른 위치 계산 |
| 카메라 제어 | 조립 방향 또는 지정 시점에 맞추고 부드럽게 회전 보간 |
| 3D 프레임 생성 | VTK 오프스크린 렌더링 |
| 안내 패널 합성 | Pillow로 프로젝트명·자재정보·주의사항 등 합성 |
| MP4 제작 | NumPy 프레임 데이터를 FFmpeg에 전달해 H.264 인코딩 |
| 결과 미리보기 | Qt Multimedia로 재생·배속·전체화면 제공 |

#### 처리 흐름

> 확정본 로드 → 시간축 생성 → 카메라 회전 → 대상 부품 점멸 → 조립 이동 → 안내 패널 합성 → 프레임 인코딩 → MP4 저장

- 기본 출력은 1920×1080, 30fps, H.264 MP4다.
- 카메라는 기준 부품 중심과 일정한 거리를 유지하며 시점을 바꾼다.
- 편집 단계의 주의사항은 같은 계획 데이터에서 읽어 자동 반영한다.
- 자재정보는 기본적으로 부품명을 표시한다.
- 주의사항이 없으면 본문은 비워두되 템플릿은 유지한다.
- 미리보기와 영상 생성은 공통 장면 계산 구조를 사용한다.
- 영상 생성 시 CAD 간섭 검사를 다시 수행하지 않는다.
- 현재 편집 내용이 확정본과 일치하는지는 확인하며, 변경됐다면 재확정을 요구한다. 이는 CAD 간섭 검사와는 별개다.

#### 발표용 설명

> 확정 순서를 시간축 기반 3D 애니메이션으로 변환하고, 작업 정보 템플릿을 합성한 프레임을 FFmpeg로 인코딩하여 조립 안내 영상을 자동 생성합니다.

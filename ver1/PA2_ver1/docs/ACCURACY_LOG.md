# 외부 공유용 성능 요약 로그

2026-10-26 추가. 기존 상세 로그를 대체하지 않으며, 자동 순서 생성·간섭 검사·학습 기준은 바꾸지 않습니다.

## 저장 위치와 수명

- 로컬 상세 기록: `PA2.exe` 옆 `log/generation_….json`. 기존 기록은 유지합니다.
- 외부 공유 대상: **`log/accuracy_log/accuracy_<독립 난수>.json`만** 전달합니다.
- 생성 실행마다 요약 하나를 만들고, 같은 실행의 확정/재확정 비교 이력은 해당 파일에 누적합니다. 재분석은 이력을 중복 추가하지 않습니다.
- 파일명/`report_id`는 프로젝트·생성·모델 ID와 별도로 생성한 UUID입니다. 로컬 상세 로그의 `accuracy_report_id`로만 대응 관계를 보관합니다.
- 생성 전/확정 전/최초 초안이 없는 과거 프로젝트에는 비교 불가 상태를 기록하며 정확도를 0 또는 100%로 만들지 않습니다.
- 실패·취소 실행은 경과 시간과 고정 상태 코드만 남기며 원문 오류는 내보내지 않습니다.
- `uninst.exe`는 이 하위 폴더에서 정확한 요약 스키마를 가진 JSON만 관리합니다. 모르는 파일·다른 하위 폴더는 보존합니다.

## 포함하는 정보

| 항목 | 내용 |
|---|---|
| 고정 메타데이터 | 스키마, 독립 report ID, 자동/수동, 고정 상태 코드 |
| 알고리즘 | 허용된 계획 알고리즘 이름/버전, 순서·방향 추천의 실제 방식, 성공 예측 횟수, 복귀 발생 여부 |
| 형상 최적화 | 선택적 보수 프록시 방식/버전, 활성화 여부, 실제 간섭 계산 생략 실적 여부 |
| 시간 | 전체 생성·탐색·네이티브 경로·방향 힌트·일반부품 초안 시간(수집된 항목만) |
| 검사 수 | 후보·실제 CAD 요청·Common·부품 쌍·캐시 재사용·탐색 상태 등의 숫자 |
| 단계 수 | 전체 대상·생성·경로 통과·미해결·체결부·예외 단계 수 및 초안/검증 완료 여부 |
| 비교 | 전체 / 일반부품 / 예외 제외 일반부품의 선후관계 일치율, LCS 비율, 방향 일치율, 표본 수 |
| 이력 | 익명 확정 버전 번호별 위 비교 지표; 추가/제외 부품은 개수만 |

일치율은 0~1입니다. 방향 일치 허용 차이는 1도입니다. 이 수치는 **사용자 확정본과의 유사도**이며 물리적 간섭 정확도가 아닙니다. 사용자 편집을 다시 CAD 검증했다고 표시하지 않습니다. 시간/검사 항목의 측정 범위는 기존 로그와 같으며 강제 종료된 네이티브 호출의 부분 카운터는 포함되지 않을 수 있습니다.

### `algorithms` 구조 (1_04 추가 보완)

- `planner`, `planner_version`: 고정 허용 목록에 있는 알고리즘 이름과 버전만 기록합니다. 알 수 없는 값은 `unknown`/`null`입니다. 프로젝트나 모델의 임의 문자열을 버전으로 복사하지 않습니다.
- `order_recommendation`, `direction_recommendation`: `method`, `prediction_calls`, `fallback_occurred`를 기록합니다. 성공한 실제 예측이 있는 역할만 `LGBMRanker`로 표시합니다. 모델이 활성화되어 있어도 이 실행에서 예측하지 않았으면 `rule_based`입니다. 예측 후 오류 복귀가 발생한 경우 `LGBMRanker_with_fallback`으로 구분하며, 복귀 대상은 이전 검증 모델 또는 규칙일 수 있습니다.
- 추천 역할의 범위는 `recommendation_scope=general_parts_only`입니다. 체결부는 `fastener_direction=geometry_axis_head_rule`로 구분하며 학습 모델의 방향 추천과 혼동하지 않습니다. 수동 생성은 `manual_fixed`입니다.
- `shape_optimization`: `method`, `version`, `enabled`, `applied`를 기록합니다. `enabled`는 반환된 CAD 실행 증거의 활성화 여부입니다. `applied=true`는 해당 실행에서 `PROXY_FACE_SWEEP_CLEAR` 또는 `PROXY_ENCLOSURE_CLEAR` 증거로 원래 Boolean/스윕 계산을 생략한 실적이 있음을 뜻합니다. 활성화/프록시 생성만으로 적용 성공이라고 기록하지 않습니다.
- 과거 기록에 활성화/버전/실제 실행 증거가 없으면 현재 환경변수나 활성 모델로 소급 추정하지 않고 `unknown`/`null`로 남깁니다. 과거 로그에 명시적 프록시 성공 카운터가 있으면 적용 실적은 복원할 수 있지만 버전은 미상일 수 있습니다. 수동 생성의 형상 최적화는 `not_applicable`입니다.
- 이 정보는 생성 당시 최초 초안·모델 예측 카운터·CAD 실행 증거에서 가져옵니다. 사용자 재확정이나 모델 교체 시 현재 설정으로 덮어쓰지 않습니다. 프로젝트/모델 ID나 모델 파일·계열명·실패 원문은 포함하지 않습니다.

## 제외하는 정보

프로젝트명·차종·품종, 프로젝트/부품/그룹/생성/확정/모델 ID, 부품명·형상, 실제 조립 순서·방향 벡터·거리·좌표·카메라, 공정/자재/주의사항 원문, STEP/DB/사용자 경로, 설정 객체, 모델 데이터, 오류/진단 원문, 생성·확정 시각은 제외합니다.

알려진 키를 복사한 다음 불필요한 키를 지우는 방식이 아닙니다. 고정 허용 목록의 숫자/불리언 및 고정 문자열만 새 객체에 넣으며 알 수 없는 중첩 필드, 문자열 숫자, NaN/Infinity, 음수 카운터는 버립니다. 향후 상세 로그 필드가 늘어나도 요약에 자동 포함되지 않습니다.

`accuracy_log`는 제품 구성 원문을 줄인 성능 요약이지 법적/통계적 익명성을 보장하는 장치는 아닙니다. 부품 수·예외 수·시간 등 통계도 회사 규정상 민감할 수 있으므로 승인된 범위에서만 공유하세요. 상위 `log` 전체, 프로젝트 DB, 모델·원본 파일은 동봉하지 마세요.

## 기존 기록에서 만들기

이후 생성·확정은 자동 기록합니다. 기존 로그는 다음 도구로 일괄 추출할 수 있습니다. 기존 상세 로그에는 대응용 난수 ID만 추가하며 최초 초안·확정본은 보존합니다.

```powershell
.\.venv\Scripts\python.exe -X utf8 tools\export_accuracy_logs.py
```

다른 설치본의 로그는 `--log-dir "C:\경로\log"`로 지정합니다. 학습/이벤트 JSON은 대상이 아니며 잘못된 생성 로그는 실패 개수로 보고합니다. 다시 실행해도 파일을 중복 생성하지 않습니다.

쓰기 실패 시 기존 DB 저장 및 상세 로그는 유지하고 경고합니다. 권한/경로 문제를 해결한 뒤 같은 도구를 재실행하면 복구할 수 있습니다. 실행 파일을 새로 빌드해도 이전에 전달한 ZIP은 자동으로 갱신되지 않습니다.

## 전체 구현 구조

PA²는 CAD 기반 조립 순서 초안을 자동으로 추천하고, 사용자가 수정·확정한 결과를 작업 안내 영상으로 제작하는 Windows 로컬 프로그램이다.

전체 흐름은 다음과 같다.

> 프로젝트 데이터 → 자동 추천 초안 → 사용자 확정본 → 조립 안내 영상

| 구현 구조 | 핵심 역할 | 다음 구조에 전달하는 데이터 |
|---|---|---|
| 프로젝트 저장·관리 | CAD 분석, 부품 구성, 프로젝트와 작업 결과 저장·복원 | 부품 그룹, 정밀 형상, 접촉 관계 |
| 자동 조립 순서 추천 | 분해 순서 탐색 후 조립 순서로 역순 변환 | 편집 가능한 조립 순서 초안과 진단 |
| 조립 순서 편집 | 순서·방향·시점·작업 정보를 수정하고 확정 | 사용자 확정본 |
| 영상 생성 | 확정본의 3D 장면과 작업 안내를 영상으로 출력 | MP4 영상 |

## 1. 프로젝트 저장·관리

### 구현 목적

CAD 파일과 분석 결과, 사용자가 편집한 순서와 생성 영상을 프로젝트 단위로 관리하고, 프로그램을 다시 실행해도 작업을 이어갈 수 있도록 구현했다.

### 사용 기술

| 기술 | 실제 사용 용도 |
|---|---|
| SQLAlchemy + SQLite | 프로젝트·부품 구성·조립 단계·확정본 등 구조화된 데이터 저장 |
| SHA-256 | 입력 파일 식별, 관리 사본과 내보내기 파일의 무결성 확인 |
| JSON | 분석 진단, 설정, 그룹 구조, 확정 순서 등의 저장 |
| BREP 캐시 | 분석한 정밀 CAD 형상을 저장해 재열기 시 활용 |
| Open CASCADE의 Python 바인딩인 OCP | STEP 파일 읽기와 형상 정보 분석 |

별도 데이터베이스 연결 설정이 없는 현재 기본 실행은 SQLite를 사용한다.

### 실제 구현 방식

- 프로젝트를 차종·품종·프로젝트명으로 구분한다.
- 입력 STEP은 원본을 직접 수정하지 않고 프로그램 관리 영역에 사본으로 저장한다.
- 완제품에서 바디를 추출하고 체적·중심·경계상자·형상 유효성을 분석한다.
- 개별 부품 STEP과 완제품 바디를 대조해 하나의 부품으로 자동 그룹화한다.
- 자동 매칭되지 않은 부품은 수동 그룹화로 보완할 수 있다.
- 분석 상태, 편집 중인 초안, 사용자 확정본을 구분해 저장한다.
- 기존 프로젝트는 저장된 부품 구성과 형상 캐시를 복원해 다시 연다.

기본 작업 데이터는 실행 파일 폴더와 분리된 `%LOCALAPPDATA%\THN\PA2`에 저장된다. 별도 데이터 경로를 지정한 환경에서는 해당 설정이 우선한다.

### 처리 흐름

> 프로젝트 생성 → STEP 관리 사본 저장 → 형상 분석·자동 그룹화 → 필요 시 수동 그룹화 → 분석 결과·형상 캐시 저장 → 프로젝트 다시 불러오기

### 발표용 핵심 문장

> 원본 CAD를 보존하면서 분석 결과와 작업 상태를 프로젝트 단위로 저장하고, 캐시를 활용해 이전 작업을 복원하도록 구현했습니다.

## 2. 자동 조립 순서 추천

### 구현 목적

완성된 제품에서 부품을 제거할 수 있는 순서를 찾고, 이를 역순으로 변환해 조립 순서 초안을 추천한다.

### 사용 기술

| 기술 | 실제 사용 용도 |
|---|---|
| OCP / Open CASCADE | 부품 간 거리·접촉·겹침 및 이동 경로 계산 |
| 접촉 그래프 | 부품 간 연결 관계와 관련 볼트·너트 파악 |
| 경계상자 기반 노출도 평가 | 바깥에 노출된 일반 부품과 이동 방향의 우선순위 결정 |
| 제한된 백트래킹 탐색 | 특정 부품이 막히면 다른 제거 순서를 시도 |
| 상태·경로·차단 근거 캐시 | 같은 검사를 반복하는 비용 감소 |
| multiprocessing | 정밀 CAD 계산을 별도 프로세스로 격리하고 시간 제한·취소 처리 |

### 실제 구현 방식

#### ① 기준 부품과 예외 부품 설정

기준 부품은 움직이지 않는 대상으로 유지한다. 사용자가 지정한 예외 부품은 간섭 검사 없이 분해 순서의 앞부분에 배치하며, 방향은 노출도를 기준으로 지정한다.

예외 부품이 먼저 배치된다는 것은 분해 순서 기준이다. 조립 순서는 전체 분해 순서를 뒤집어 구성한다.

#### ② 일반 부품의 순서부터 탐색

볼트·너트를 제외한 상태에서, 외부에 더 노출된 일반 부품을 우선 검사한다. 부품 하나를 제거하면 남은 부품 구성을 기준으로 우선순위를 다시 계산한다.

#### ③ 이동 방향과 경로 검사

일반 부품은 ±X·±Y·±Z의 6방향을 사용한다.

- 가장 넓은 평면 접촉면에서 멀어지는 방향을 우선한다.
- 초기 겹침이 있거나 접촉면 방향을 얻기 어려우면 노출도 순위를 사용한다.
- 우선 방향부터 경로를 검사하고, 통과하면 해당 부품의 나머지 방향 검사는 생략한다.
- 초기 겹침 허용 정책을 적용하되, 일반 경로 검사와 구분해 결과를 기록한다.

초기 겹침 허용은 모든 간섭을 무시한다는 의미가 아니다. 초기 겹침에 대한 정책을 적용하면서 경로 판정을 수행하며, 계산 실패나 미판정도 진단에 남긴다.

#### ④ 볼트·너트 단계 삽입

일반 부품의 초안이 만들어지면 접촉 관계를 이용해 관련 체결부를 배치한다.

분해 기준으로는 관련 일반 부품보다 먼저 제거되도록 삽입한다. 볼트는 머리 쪽 축 방향을 우선 사용하며, 체결부의 상세 이동 경로 검사는 생략한다.

#### ⑤ 조립 순서로 변환

분해 순서를 뒤집고 이동 방향을 반대로 바꿔 조립 순서를 만든다. 해결되지 않은 일반 부품도 검토 대상으로 남겨 사용자가 편집할 수 있는 전체 초안을 구성한다.

따라서 전체 단계가 포함된 초안과 모든 부품의 경로 검증을 통과한 결과는 구분해야 한다. 작업 취소나 입력·분석 단계의 오류까지 무조건 전체 초안으로 처리하는 것은 아니다.

### 처리 흐름

> 기준·예외 지정 → 체결부 제외 → 일반 부품 우선순위 선정 → 방향·경로 검사 → 잔여 상태 갱신·반복 → 미해결 부품 보완 → 체결부 삽입 → 역순 변환 → 조립 초안 저장

### 발표용 핵심 문장

> 일반 부품의 분해 가능성을 먼저 탐색하고 체결부를 후삽입하는 방식으로 정밀 검사량을 줄인 뒤, 분해 순서를 역순으로 변환해 조립 초안을 추천합니다.

### 발표 시 구분할 사항

- 자동 추천은 사용자 검토용 초안이며, 자동 검증이 완료된 최종 작업 지시를 의미하지 않는다.
- 현재 GUI의 기본 추천은 기하·규칙 기반이다. 학습된 머신러닝 모델이 현재 기본 순서를 결정하는 구조는 아니다.
- 학습 데이터 저장과 LightGBM 관련 코드는 존재하지만, 현재 기본 추천 알고리즘과 구분해 설명해야 한다.

## 3. 조립 순서 편집

### 구현 목적

자동 추천이 반영하지 못하는 실제 작업 조건과 작업자의 판단을 사용자가 직접 보완하고 확정하도록 구현했다.

### 사용 기술

| 기술 | 실제 사용 용도 |
|---|---|
| PySide6 / Qt Widgets | 부품 목록, 가로 순서 카드, 작업 속성 등 편집 인터페이스 |
| VTK | 3D 모델 표시, 선택 부품 하이라이트, 형상 미리보기 |
| Qt Signal/Slot·QTimer | 선택 상태 동기화와 미리보기 재생 |
| 계획 데이터 복사·이력 관리 | 실행 취소·다시 실행, 임시 미리보기 |
| 확정 스냅샷·내용 해시 | 편집본과 확정본 구분, 수정 후 재확정 여부 확인 |

### 실제 구현 방식

- 순서를 부품 형상 미리보기가 포함된 가로 카드로 표시한다.
- 카드를 선택하면 해당 부품이 3D 모델에서 하이라이트된다.
- 다중선택한 단계를 내부 순서를 유지한 채 함께 이동할 수 있다.
- 작업 속성에서 방향·이동 거리·카메라 시점·공정 문구·자재정보·주의사항을 편집한다.
- 선택 단계의 미리보기는 입력 중인 방향과 카메라를 임시 적용해 재생하고, 종료 후 기존 화면 상태로 돌아온다.
- 편집 내용은 실행 취소·다시 실행할 수 있다.
- 수동 편집에서는 간섭 재검사 없이 사용자 수정값을 적용한다.
- 최종적으로 ‘순서 확정’을 수행하면 별도의 확정본을 저장한다. 이후 다시 수정하면 영상 생성 전에 재확정해야 한다.

수동 그룹화는 같은 모델 화면에서 제공하지만, 순서 생성 전의 부품 구성 편집에 해당한다. 그룹 구성이 바뀌면 순서를 다시 생성해야 하며, 자동 그룹은 해제할 수 없고 수동 그룹만 해제할 수 있다.

부품 목록에서 둘 이상 선택하면 선택 부품만 3D 화면에 표시해 그룹화 대상을 확인할 수 있다. 이 표시 기능은 순서 카드의 다중선택에는 적용하지 않는다.

### 처리 흐름

> 초안 불러오기 → 카드 선택·3D 확인 → 순서·방향·작업 정보 수정 → 선택 단계 미리보기 → 수정값 적용 → 순서 확정 → 확정본 저장

### 발표용 핵심 문장

> 자동 추천 결과를 3D 모델과 순서 카드로 확인하고, 사용자가 작업 조건에 맞게 수정한 뒤 별도의 확정본으로 저장하는 검토·편집 구조입니다.

## 4. 영상 생성

### 구현 목적

사용자가 확정한 조립 순서를 작업자가 이해하기 쉬운 3D 조립 안내 영상으로 변환한다.

### 사용 기술

| 기술 | 실제 사용 용도 |
|---|---|
| VTK 오프스크린 렌더링 | 조립 장면을 화면 캡처가 아닌 프레임 이미지로 생성 |
| NumPy | 카메라 계산과 프레임 데이터 처리 |
| Pillow | 로고·문구·자재정보·주의사항 템플릿 합성 |
| FFmpeg | 프레임을 H.264 MP4 영상으로 인코딩 |
| Qt Multimedia | 생성 영상의 내장 재생·배속·전체화면 미리보기 |

### 실제 구현 방식

#### ① 확정본 확인

현재 편집 내용이 확정본과 일치하는지 확인한다. 수정 후 재확정하지 않았다면 영상 생성을 막는다. 이는 내용 일치 검사이며, CAD 간섭 재검사는 아니다.

#### ② 시간축 구성

각 단계에 다음 재생 구간을 배정한다.

> 카메라 회전 → 대상 부품 하이라이트 점멸 → 하이라이트를 유지하며 조립 이동 → 다음 단계

카메라는 기준 부품 중심과 일정한 거리를 유지하고, 시점 전환에는 부드러운 회전 보간을 사용한다.

#### ③ 프레임 생성과 템플릿 합성

매 시각의 부품 위치·표시 상태·카메라를 계산해 3D 프레임을 렌더링한다. 여기에 프로젝트 정보와 작업 안내 패널을 합성한다.

- 자재정보는 기본적으로 부품명을 표시한다.
- 주의사항은 사용자 입력이 없으면 본문을 비운다.
- 내용이 없어도 템플릿 영역은 유지한다.

편집 미리보기와 영상 생성은 공통 장면 계산 구조를 사용한다. 영상 생성에서는 같은 구조를 이용해 각 프레임의 상태를 계산하고 출력한다.

#### ④ 인코딩·재생·관리

기본 출력은 1920×1080, 30fps, H.264 MP4다. 사용 가능한 인코더를 시험해 선택하며, 지원되는 환경에서는 하드웨어 인코더도 사용할 수 있다. 하드웨어 인코딩이 실패하는 경우 소프트웨어 인코딩으로 재시도하는 처리가 있다.

생성 진행도는 처리한 프레임 수로 표시한다. 완성 영상은 내장 재생, 배속, 전체화면·Esc 해제, 내보내기를 지원한다.

‘최신 버전만 남기기’는 현재 프로젝트의 정상 완료 영상 중 최신 한 개를 유지하고 이전 완료 영상을 정리한다. 다른 프로젝트나 별도로 내보낸 복사본은 삭제 대상으로 삼지 않는다.

### 처리 흐름

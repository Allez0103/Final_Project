# v21 공통 학습 주기·추천 모델 관리

## 이번 요청과 실행 범위

2026-10-22: 학습 기능은 구현하되 **학습 실행 및 학습 검증은 하지 않는다**. 사용자가 프로그램에서 더미 프로젝트를 준비한 다음 별도 요청으로 학습·검증한다. 임의 학습 데이터나 모델은 생성하지 않는다. 자동 학습·자동 적용의 기본값은 모두 OFF다. ZIP은 갱신하지 않는다.

기존 순서/간섭/체결부/수동 편집/영상 정책은 유지한다. 기존 확정본·영상은 모델 교체와 무관하며 다시 쓰지 않는다. v20 실측을 이번 버전의 모델 성능으로 인용하면 안 된다.

## 두 모델

| 구분 | 모델 | 입력 | 출력·적용 범위 |
|---|---|---|---|
| 일반 부품 순서 | LightGBM LGBMRanker | 현재 남은 일반 부품의 크기·상대 위치·부품 종류·기준 부품 거리·저장 접촉 그래프·잔여 상태 | 다음 검사 후보의 점수·우선순위 |
| 일반 부품 분해 방향 | LightGBM LGBMRanker | 같은 부품 특징 + 기존 6축 각각의 방향벡터·AABB 가림 정도·접촉 상대 중심에서 멀어지는 정도·방향별 크기 | 기존 6축의 점수·검사 순서 |

학습 특징을 만들기 위한 새로운 BREP 거리/접촉/Boolean 계산은 추가하지 않는다. 방향 특징은 학습·추천에서 같은 함수로 만든다. 임의 각도의 사용자 방향은 기록은 보존하지만 6축 정답으로 강제 변환하지 않는다.

추천기는 `TwoStagePriorityProvider`의 하위 클래스로 구현했다. 일반 부품 탐색 → 체결부 삽입 구조를 유지한다. 첫 경로 PASS에서 다음 방향 검사를 생략한다. 예외 부품의 선제 제거/노출도 방향, 체결부의 연결·축/머리 방향은 학습으로 변경하지 않는다. 모델은 자동 간섭 예외를 부여하지 않는다. 수동생성에는 두 모델을 사용하지 않는다.

## 공통 데이터와 주기

1. 확정 시 기존 관찰 기록을 자동 수집한다. 추가 사용자 입력은 없다.
2. 프로젝트별 최신 **완전 확정본**, 동일 관찰의 중복을 제외해 공통 스냅샷을 고정한다. 실제 학습과 평가가 끝날 때까지 같은 데이터·모델 기준·설정을 사용한다.
3. 초기 기준: 독립 형상 계열 30개 이상 AND 일반 부품 선택 상태 1,000개 이상.
4. 재학습: (직전 완료 주기 이후 최소 24시간) AND (신규 계열 5개 이상 OR 신규 선택 상태 500개 이상).
5. 계열/상태의 식별자 집합 차이로 신규량을 계산한다. 동일 확정 반복과 방향만 바꾼 확정이 같은 순서 상태를 반복 증가시키지 않는다.
6. 계열 ID를 정렬해 매 5번째 계열을 평가용으로 분리한다. 같은 계열의 프로젝트/확정/상태는 양쪽에 섞지 않는다. 두 모델은 같은 분리 목록을 사용한다.
7. 순서 모델을 저장한 후 방향 모델을 학습한다. 동시에 두 모델을 학습하지 않는다. 방향은 학습용 100사례, 최소 2축, 각 축 10사례 기준을 기본으로 한다. 부족하면 방향만 보류하고 기존 방향 모델/규칙을 유지한다.

형상 계열은 기존 체적·바운딩 박스·바디 중심 간 거리 지문 기반이다. 같은 제품 계열 전체를 완벽하게 판별하는 분류기는 아니며 유사 제품 변형에 대한 데이터 누수 위험은 후속 검증 대상이다. 단순 STEP 파일 개수나 같은 모델의 복사 프로젝트 개수만으로 독립 계열 수를 늘려서는 안 된다.

확정 선호에는 예외 부품도 포함한다. 다만 실제 경로 PASS/BLOCKED/UNKNOWN, 사용자 편집, 예외는 별도 근거로 보존한다. 이 두 모델의 목표는 사용자 선택 선호이며 UNKNOWN/NOT_TESTED/예외를 물리 실패·통과 라벨로 사용하지 않는다.

## 평가와 적용

- 먼저 저비용 순서 투영·teacher-forced 순서/방향 선호를 비교한다. CAD를 실행하지 않는 사전 필터이며 방향의 정밀 접촉면 규칙을 완전히 재현한 검증으로 취급하지 않는다.
- 선호 악화가 허용 폭 이내이고 개선 신호가 있는 조합만 실제 CAD 비교로 보낸다.
- 비교 조합: 현재 순서+현재 방향, 신규 순서+현재 방향, 현재 순서+신규 방향, 신규 순서+신규 방향. 학습만 완료했다고 두 모델을 동시에 적용하지 않는다.
- 실제 CAD 비교는 저장된 BREP·접촉 그래프·동일 설정/기준 부품/예외 조건으로 수행한다. 기존 규칙 또는 현재 적용 모델이 실제 비교 대상이다. 과거 `train-ranking` 실험의 작은 체적 우선 기준은 적용 판단에 사용하지 않는다.
- 새 BREP 캐시가 없거나 접촉 그래프가 미완성/다른 정책이면 적용하지 않는다. 외부 STEP 재분석이나 기존 프로젝트 수정으로 평가를 강제하지 않는다.
- 평가 형상의 해시를 고정한다. 평가 중 변경/누락은 실패 처리한다.
- 기본 2회 반복하며 실행 순서를 번갈아 배치한다. 실행 단위 결과를 저장하고 다음 유휴 구간에 이어서 진행한다. 완료하지 못한 실행을 성공 결과로 넣지 않는다.
- 지표: 일반 부품·예외 제외 선후 관계 유지율, LCS, 방향 일치율(1도), 실제 신규 경로 요청, 후보 기록, 시간, 상태당 검사 방향 수, 첫 방향 PASS 비율. 전체/일반 지표도 별도 보존한다.
- 평가 집계는 프로젝트 반복 평균 → 계열 평균 → 전체 계열 평균이다. 큰 제품/많은 체결부가 평균을 독점하지 않는다.
- 단계 수뿐 아니라 실제 경로 검증 단계 수, 미해결·UNKNOWN·시간 초과·오류도 사례별로 비교한다. 채워진 전체 초안을 물리 검증 완료로 세지 않는다.

초기 적용 기준(설정 가능):

- 각 사례의 생성/경로 검증 단계 감소, 미해결/UNKNOWN/시간 초과/오류 증가를 허용하지 않는다.
- 순서·방향 선호는 각각 1%p 이상 악화하지 않아야 하며, 개별 사례의 순서 선호 5%p 이상 하락도 차단한다.
- 시간·신규 경로·후보 기록의 계열 평균 비율이 각각 기존 대비 1.05 이내여야 한다.
- 위 조건 아래 순서 또는 방향 선호 +3%p 이상, 또는 시간/신규 경로 요청 10% 이상 감소 시 적용 후보로 인정한다.

수치들은 아직 실제 고객 데이터로 검증한 최적값이 아니다. 이후 더미 프로젝트 시험에서 확인하고 조정해야 한다. 시간 비교는 유휴 백그라운드에서의 동일 자원 조건 비교이며 사양이 다른 PC의 절대 실행 시간을 보장하지 않는다.

## 유휴 실행·자원·복원

- 설정에서 허용한 경우에만 앱 입력/전경 작업/미리보기/영상 재생이 없는 유휴 구간에 진행한다. 기본 입력 유휴 120초.
- 별도 프로세스 한 개, 학습 수치 연산 1스레드, 지원 OS에서 한 CPU 코어·낮은 우선순위. 실제 비교의 CAD Boolean도 동일하게 1스레드다.
- 기본 구간 예산 1,800초, 자식 CAD 프로세스 포함 RSS 합계 1,536MiB. 초과 시 중단·보류한다. 한 번의 CAD 실행이 구간 안에 끝나지 못하면 그 실행은 다시 해야 하므로 설정 조정이 필요할 수 있다.
- 클릭/키보드/휠/마우스 이동, 전경 작업, 설정 변경 시 중단한다. 저장된 모델 역할과 완성된 평가 실행만 재사용한다. 학습 중이던 나무 자체를 중간부터 이어 학습하지 않는다.
- OS 파일 잠금으로 같은 데이터 폴더의 중복 학습 작업을 막는다. 부모 프로세스 종료 감시와 소유 자식 프로세스 종료 처리가 있다. 별도 상시 서비스는 설치하지 않는다.
- `learning/bundles/<id>`에 텍스트 모델·역할/특징 스키마·라이브러리 주버전·체크섬·분리 계열 목록을 보관한다. pickle 모델을 임의 실행하지 않는다.
- `learning_cycles`에 공통 주기/진행·데이터·설정·비교 근거, `model_activations`에 원자적 순서·방향 쌍 변경 이력을 추가한다. 기존 테이블·확정본을 덮어쓰지 않는다.
- 자동생성 시작 시 모델 쌍을 고정한다. 교체는 다음 생성부터 적용하며 전경 생성마다 비교용 CAD를 중복 실행하지 않는다.
- 파일 손상/입력 스키마·라이브러리 불일치/비유한 예측은 이전 검증된 **쌍** 또는 기존 두 단계 규칙으로 복원한다. 검증하지 않은 역할 조합을 임의로 만들지 않는다.
- 학습 현황에서 현재 모델, 주기/진행 단계/보류 사유/이력, `평가 통과 모델 적용`, `이전 모델로 복원`을 제공한다. 적용 당시 기준 모델이나 설정이 바뀌었으면 적용을 보류한다.

## 이후 검증 절차 — 이번에는 실행하지 않음

1. 사용자가 실제 앱에서 더미 프로젝트의 자동/수동 초안·편집·방향 변경·예외·확정 데이터를 준비한다.
2. 독립 형상 계열 수와 실제 선택 상태 수를 확인한다. 반복 복사 프로젝트는 독립 계열로 보지 않는다. 부족한 데이터로 억지 실용 성능을 주장하지 않는다.
3. 별도 복사 데이터 폴더에서 학습 임계값·유휴 중단/재개·두 모델 순차 학습·동일 계열 분리·방향 데이터 보류를 시험한다.
4. 기존 규칙/현재 모델 대비 분리 계열의 선호·실제 검사 수/시간·단계/미판정/오류와 조합별 적용 판정을 확인한다.
5. 모델 손상/비유한 예측/설정 변경/프로그램 종료/이전 모델 복원과 다음 작업부터 적용 여부를 시험한다.
6. 적절한 모델이 없으면 기존 규칙 유지가 정상 결과다. 성능 개선량은 이 시험 후에만 기록한다.

명시적 공통 주기 실행 경로는 `learning-cycle --data-root <복사 데이터 폴더>`이며 자동 적용하지 않는다. 기존 `train-ranking`은 이전 오프라인 단일 모델 실험 경로로만 남겨 두었다. 이 명령들은 이번 작업에서는 실행하지 않았다.

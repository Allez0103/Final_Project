# PA² 구조와 핵심 계약

## 모듈

```text
src/pa2/
  ui/            PySide6 3화면, 설정 창, 편집/미리보기
  application/   프로젝트, import, 계획 저장·확정 서비스
  domain/        판정 enum, 좌표·계획·그룹 데이터 계약
  cad/           OCP STEP, BREP 캐시, 그룹화, 방향, 접촉, 경로, 지지
  planning/      공통 탐색 엔진과 기본 우선순위
  learning/      특징 v1, teacher forcing, LGBMRanker
  rendering/     공통 scene_at 시간축과 VTK 장면
  video/         Pillow 템플릿 합성과 FFmpeg H.264 인코딩
  storage/       SQLAlchemy 스키마, 불변 자산, 단계 캐시
  jobs/          spawn 프로세스 작업·취소 기반
```

## 보수적 판정

경로 결과는 `PASS/BLOCKED/UNKNOWN`입니다. 화면 메시나 고정 간격 샘플만으로 PASS를 만들지 않습니다. 초기 형상과 경계 면의 연속 이동 체적으로 전체 경로를 검사하며, 시작과 끝 사이의 얇은 장애물도 실제 BREP 교차 체적으로 확인합니다. 전체 경로를 증명하지 못하면 UNKNOWN입니다.

2026-10-18: 접촉·방향·경로의 정밀 호출은 `NativeCadSession`과 재사용 spawn worker에서 실행합니다. 그룹 BREP 작업 사본의 경로·ID·구조 데이터만 전달하고 CAD 객체는 pickle하지 않습니다. 부모는 각 native 연산의 시작 이벤트를 받아 `min(native 제한, 후보 잔여, 전체 잔여)`를 감시합니다. 시간 초과·프로세스 비정상 종료는 UNKNOWN, 취소는 CANCELLED이며 해당 프로세스를 종료·회수합니다. 다음 후보는 새 프로세스를 시작할 수 있습니다.

접촉 그래프는 그룹→솔리드→면의 보수적 경계 상자로 후보를 줄인 뒤 BREP 정점의 내부/경계 분류 또는 실제 면 거리를 근거로 그룹당 한 간선을 만듭니다. 초기 관통은 BREP 교차 체적으로 검사합니다. 접촉·슬라이드 경로는 초기 형상과 각 경계 면의 평행이동 prism이 전체 이동 영역을 덮는 성질을 이용합니다. 유효성을 확인한 모든 체적 prism과 장애물의 교차를 검사하고 종점 분리까지 증명해야 PASS입니다. 평행 평면·축 방향 원통면은 체적을 만들지 않는 면으로 처리합니다. 실패한 Boolean, 잘못된 prism, 시간 초과는 UNKNOWN입니다.

`path-v7-curved-sweep` 보강: 실패한 원통·원뿔 prism을 투영 윤곽에서 분할하고, 기타 면은 보수적인 패치 이동 경계 상자로 검사합니다. 덮개 교차는 실제 충돌 확정이 아니며, 모든 덮개가 비어 있는 경우만 경로 증거로 인정합니다. 정밀 위치 검사는 실제 충돌 증거로만 사용합니다. 시작 AABB가 분리된 미해결 쌍에는 5초 예산의 연속 거리 구간 증명(거리 함수의 1-Lipschitz 성질)을 보조 적용합니다. 예산은 구간 진입 시 확인하고 진행 중 native 연산은 상위 native·후보·전체 제한을 따릅니다. 증명 실패·Boolean 실패·시간 초과는 UNKNOWN이며 고정 간격 위치 검사만으로 PASS를 만들지 않습니다.

입력은 경로 계산 전에 정밀 BREP 유효성을 검사합니다. 위상은 유효하지만 기하 정밀 검사가 실패한 형상은 깊은 계산용 사본에서 SameParameter 정합성 보정만 시도합니다. 허용오차·경계 변화 ≤ epsilon, 위상 개수 동일, 체적 변화 ≤ max(1e-9 mm³, 원래 체적×1e-8), 보정 후 정밀 유효성을 모두 요구합니다. 원본·캐시 BREP는 변경하지 않습니다. 채택 경로의 보정은 `input_repairs`, 단계 주의사항, REVIEW_REQUIRED 상태에 기록됩니다. 상세 근거는 [미판정 수정 보고서](UNKNOWN_RESOLUTION_REPORT.md)를 확인하세요.

## 좌표

2026-10-18 사용자 승인 정책 변경: `path-v4-initial-region`은 부품 종류·이동 방향에 관계없이 유효 형상 쌍의 초기 겹침 영역을 허용합니다. 계산용 상대 형상 `O' = O \ M(0)`에 대해 전체 sweep을 검사하므로 허용 영역은 원래 교차 영역으로 고정됩니다. 원본·관리 BREP는 바꾸지 않습니다. 종점은 원래 상대 형상 O와 분리되어야 합니다. 유효한 차집합이 빈 체적이면 새 간섭 검사 대상은 없지만 원래 형상과의 종점 분리는 계속 검사합니다. 실패한 Cut 또는 sweep은 UNKNOWN입니다. 예외 내역은 `PathCheckResult.evidence.initial_region_exceptions`와 단계 주의사항에 남기며, 예외가 채택된 계획은 REVIEW_REQUIRED입니다. native 검사기 캐시 키에도 정책 옵션을 포함합니다. 이전 볼트 축 방향 예외는 전체 부품 옵션을 끈 경우에만 별도 적용됩니다.

지지 UNKNOWN의 초안 허용 역시 사용자 승인 정책입니다. 경로 PASS만 채택하고 지지 증거를 별도로 기록하며, 해당 계획은 REVIEW_REQUIRED, 해당 단계는 SUPPORT_UNVERIFIED로 저장합니다. 경로의 BLOCKED/UNKNOWN 판정은 변경하지 않습니다. 전체 형식 검사와 사용자 확정 절차도 유지합니다.

- 내부 단위: mm, mm², mm³, 초
- 오른손 좌표계, 중력 `(0,0,-1)`
- 행렬: 열벡터 `p_world = T_world @ p_local`, JSON은 행 우선 16수
- 분해 종점: `Translate(removal_direction * travel_mm) @ T_final`
- 조립 방향은 분해 방향의 정확한 역방향

`Plan.validate()`가 그룹 중복/누락, 기준 부품 제외, 방향 정규화, 양의 유한 거리, 카메라 모드를 검사합니다. 사용자 편집 후 CAD 검사는 다시 호출하지 않고 `USER_CONFIRMED_UNCHECKED`를 기록합니다.

## 저장과 캐시

`planner-v11-target-fastener-dedup`는 기본 후보 선정을 기준 부품에서 먼 일반 부품 → 실제 차단/접촉 볼트·너트 → 제거마다 대상 재시도 → 다른 대상/전체 후순위 후보로 변경합니다. 남은 ID 집합별 완료된 부품 판정과 탐색 완료 상태를 재사용하고, 같은 부품의 다른 통과 방향으로 동일 자식 상태를 다시 방문하지 않습니다. 다른 상태의 차단 결과는 동일 이동·정책 및 차단 상대의 잔존이 확인될 때만 재사용합니다. 경로 정책 v10은 변경하지 않습니다. 신규 native 요청·부품 쌍 계산·캐시 재사용·중복 상태 건너뛰기와 실행 시간을 분리 계측합니다. [선정 구조 및 재검사 조건](TARGET_FASTENER_SEARCH.md).

`path-v10-decreasing-overlap-review` / `planner-v10-decreasing-overlap-review`는 사용자 승인에 따른 초기 겹침 감소 예외를 추가합니다. 감소 옵션은 전체 부품 초기 예외 옵션이 켜졌을 때만 적용되며 native checker·쌍 캐시 키에 포함됩니다. 최대 0.5 mm 간격의 겹침 부피가 누적 최저값보다 증가하면 차단하고, 교차가 해소된 첫 위치부터 나머지 연속 이동을 검사합니다. 검사 위치 사이 및 같은 상대 내 국소 충돌 없음은 증명하지 않으므로 별도 evidence·단계 경고와 REVIEW_REQUIRED 상태를 남깁니다. [정책 상세](DECREASING_OVERLAP_POLICY.md).

자산 키는 내용 SHA-256입니다. 형상 캐시 키는 단계명, 순서가 있는 입력 해시, 단계 버전, 관련 설정, 스키마 버전만 사용합니다. 작업 ID는 공용 키에 들어가지 않습니다. STEP 파싱 결과는 body별 BREP와 JSON 특징으로 저장되어 재열기에서 외부 원본과 STEP 파서를 건너뜁니다.

`step-import-v2-binary-brep` / `path-v8-binary-curved-sweep`부터 새 캐시와 worker 전달 파일은 바이너리 `.binbrep`입니다. 텍스트 round-trip에서 릴레이 4바디의 위상 유효성 손실이 재현되어 저장 방식을 변경했습니다. 기존 `.brep` 읽기는 호환성을 위해 유지합니다. 새 버전 캐시가 없으면 관리 영역 STEP을 한 번 재파싱하고 바디 ID 일치를 확인한 후 별도 키로 게시합니다. 기존 캐시·스냅샷·확정본·외부 STEP은 덮어쓰지 않습니다. 이 최초 캐시 재생성에서는 STEP 파싱 시간이 다시 필요합니다. 접촉 그래프 버전도 올려 새 표현으로 재검사합니다.

한 번의 native 탐색 세션에서는 동일 형상 쌍·경계·방향·거리·오차·초기 영역 정책의 판정을 최대 4096개 LRU로 재사용합니다. CAD 형상은 고정되어 있으므로 다른 부품을 제거한 상태에서도 그 쌍의 판정은 같습니다. 매 상태에서 남은 모든 상대 부품을 다시 순회하므로 미판정 상대가 제거되면 해당 UNKNOWN도 더 이상 적용되지 않습니다. 후보 시간 초과는 저장하지 않고 native 프로세스 재시작 시 메모리 캐시는 사라집니다. 이 캐시는 형상·방향·정책이 바뀐 검사나 다른 장애물 검사를 생략하지 않습니다.

SQLAlchemy 스키마는 프로젝트·자산·스냅샷·형상·그룹·접촉·작업·계획·확정·학습 행·모델·평가·캐시·설정·영상을 포함합니다. 개발 fallback은 SQLite이며 `PA2_DATABASE_URL=mysql+pymysql://...`로 MariaDB에 연결합니다.

## 학습

LightGBM은 후보 검사 순위만 바꿉니다. 확정 순서를 뒤집어 제거열을 만들고 teacher forcing으로 상태별 후보 행을 저장합니다. 선택 후보 relevance=1, 나머지=0이며 0을 물리적 실패로 해석하지 않습니다. 독립 계열 30개와 유효 state 1,000개 전에는 모델 학습/승격을 보류합니다.

## 장면과 영상

v12는 외부 노출 근사 우선순위와 체결부 가상 제거 사전 검사를 사용한다. 가상/실제 경로 증거는 분리하며, 실제 제거 경로·지지 정책을 통과한 단계만 최장 제거열에 저장한다. 부분 영상은 부분 상태에서만 허용하고 미계획 그룹을 원위치에 유지한다. [설계와 검증 도구](EXTERIOR_VIRTUAL_SEARCH.md).

미리보기와 영상은 `scene_at(plan, t)` 및 같은 easing을 사용합니다. 영상은 VTK 오프스크린 장면, Pillow의 한글/템플릿 합성, 번들 FFmpeg의 `libx264 + yuv420p` 파이프로 생성합니다. 완성 파일은 임시 MP4의 성공·크기를 확인한 후 공개하고 내보내기는 해시를 재검증합니다.

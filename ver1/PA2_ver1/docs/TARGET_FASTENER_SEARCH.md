# 대상 부품 중심 후보 선정과 중복 탐색 억제 (v11)

사용자 승인에 따른 탐색 순서 변경입니다. 경로 판정은 기존 `path-v10-decreasing-overlap-review`를 유지합니다. 초기 겹침 감소 예외·지지 미검증은 여전히 검토용이며 전체 순서 또는 실제 작업 안전성을 보장하지 않습니다.

## 후보 선정

1. 기준 부품을 제외한 유효 그룹 중 볼트·너트가 아닌 대상 부품을 먼저 선택합니다. 기준 부품의 체적 중심과 대상 체적 중심 사이 거리가 먼 순서이며, 중심이 없으면 경계 상자 중심을 씁니다. 동률은 접촉 수, ID 순서입니다.
2. 대상의 직선 제거 방향을 검사합니다. 통과하면 제거합니다.
3. 대상이 통과하지 못하면 실제 차단 상대에 포함된 볼트·너트를 먼저, 나머지 접촉 볼트·너트를 다음으로 시도합니다. 실제 차단 상대는 접촉 그래프에서 빠졌더라도 포함합니다. 접촉만으로 체결 관계를 확정하지 않습니다.
4. 한 체결 부품이 막혀도 다른 관련 체결 부품을 계속 시도합니다. 하나 제거할 때마다 원래 대상을 최우선으로 재시도합니다. 필요가 없어졌는데도 접촉 체결 부품 전부를 먼저 제거하지 않습니다.
5. 진전이 없으면 다음 일반 부품을 시도합니다. 마지막에는 남은 후보를 모두 대상으로 하는 후순위 경로를 둡니다. 관련 대상이 없는 볼트·너트도 배제하지 않습니다.
6. 사용자가 지정한 별도 우선순위 공급자는 그대로 사용합니다. 새 기본값은 `target-fastener-v1`입니다.

## 중복 제거와 재검사 조건

- 상태는 제거 이력이 아니라 **남은 그룹 ID 집합**으로 식별합니다. 나머지 형상은 원래 위치 그대로 있고 제거 부품은 이후 장애물에서 제외된다는 기존 모델에 근거합니다.
- 동일 상태·부품의 완료된 방향 판정을 재사용합니다. 같은 상태·부품·방향·거리는 진단에 한 번만 기록합니다.
- 한 부품에 대해 통과 방향을 하나 확보하면 같은 부품의 다른 통과 방향으로 동일한 자식 상태를 다시 만들지 않습니다. 부품을 일부만 이동시키거나 제거 방향에 따라 잔여 형상이 달라지는 모델로 확장할 경우 이 가정부터 변경해야 합니다.
- 후보와 자식 상태를 모두 열거한 상태만 이번 실행의 탐색 완료 집합에 넣습니다. 취소·전체 시간 제한·깊이/횟수 제한으로 중단한 상태는 탐색 완료로 표시하지 않습니다. 미판정이 포함된 탐색 완료는 물리적 불가능의 증명이 아닙니다.
- 다른 상태의 차단 결과는 이동 부품·방향·이동 거리가 모두 같고, 그 차단 상대가 여전히 남아 있을 때만 재사용합니다. 한 실행 안에서 형상·정밀도·예외 정책은 고정입니다. 차단 상대가 제거되거나 이동 거리가 바뀌면 재검사합니다. PASS 또는 UNKNOWN을 다른 상태의 전체 경로 결과로 재사용하지 않습니다.
- 기존 탐색 시간·역추적 깊이/횟수 설정은 유지합니다. 깊이 제한에 도달한 분기는 미완료로 남습니다. 유한 방향·예산 제한 탐색이므로 최장 가능 순서를 증명하는 알고리즘은 아닙니다.

## 검사 수와 시간의 의미

- `tested_candidates`: 중복 없는 상태+부품+방향+거리 진단 레코드 수. 새 계산과 다른 상태의 유효 차단 근거 재사용을 포함합니다.
- `native_path_calls`: 격리 CAD 프로세스로 보낸 신규 경로 요청 수. 내부 부품 쌍 캐시를 사용할 수 있으므로 Boolean 연산 수와 같지 않습니다.
- `blocked_witness_cache_hits`: 다른 상태의 유효 차단 근거를 재사용한 수. 해당 레코드의 이번 계산 시간은 0으로 기록하고 원래 계산 시간과 출처 상태를 별도 보존합니다.
- `group_evaluation_cache_hits`, `closed_state_skips`, `duplicate_group_skips`: 부품 판정 재사용, 탐색 완료 상태 건너뛰기, 같은 상태에서 공유 체결 부품 등 중복 후보 건너뛰기 수입니다.
- `pair_calculations`, `pair_cache_hits`: 반환된 신규 경로 요청 안에서 발생한 부품 쌍 계산/캐시 사용 수입니다.
- `brep_common_calls`: 경로 검사 활동 계측의 BREP_COMMON 호출 수입니다. 모든 CAD 작업의 합계는 아닙니다. 강제 종료된 네이티브 요청의 부분 작업 횟수는 반환되지 않으므로 별도 `native_calls_without_counters`를 확인해야 합니다.
- `elapsed_sec`: 지지 판정과 탐색을 포함한 Planner 실행 시간. `native_path_elapsed_sec`: 신규 경로 요청 대기 시간의 합계. 입력 재열기/접촉 준비는 보고서의 `contact_elapsed_sec`로 따로 기록합니다.

기존 v10의 9,871회는 캐시 재조회도 포함한 레코드 수입니다. 고유 상태+후보는 2,674개, 중복은 7,197개였습니다. 당시 신규 네이티브 요청/Boolean 횟수를 직접 계측하지 않았으므로 이를 신규 수치와 같은 종류라고 단정하지 않습니다.

## 검증

`tests/test_target_search.py`는 거리 우선순위, 실제 차단 체결 부품 우선, 한 체결 부품 실패 후 계속 시도, 체결 부품마다 대상 재시도, 다른 대상/고립 체결 부품 후순위 처리, 동일 잔여 집합 중복 제거, 거리/차단 상대 변경 시 캐시 무효화, UNKNOWN의 상태 간 재사용 금지, 미완료 상태의 탐색 완료 처리 금지를 검사합니다.

실측 비교는 `tools/compare_planning_runs.py`로 같은 설정·그룹·기준 부품·경로 정책인지 검증한 후 생성합니다. 이 도구는 보존한 순서의 각 단계에 해당 상태의 통과 근거가 있는지, 역순 조립 계획·검토 경고·감소 샘플 근거·차단 재사용 계측이 일치하는지도 확인합니다. 기존 사용자 초안/확정 계획과 참고 원본은 덮어쓰지 않습니다.

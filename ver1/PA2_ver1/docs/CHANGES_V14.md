# v14 적용 정책

이번 대화에서 합의한 변경으로 원 명세의 일부 기본 동작을 대체한다.

1. 새로 만든 이동 검사 솔리드의 무한점이 내부인 경우 방향을 반전하고, 유한 영역·양의 체적·BREP 유효성을 재확인한다. 계산 입력 원본은 수정하지 않는다. 초기 겹침 감소 허용과 새 간섭 차단 기준은 유지한다.
2. 전체 체결부를 제외한 일반 부품 초안으로 우선순위를 구성한다. 실제 상태에서는 일반 부품을 먼저 검사하고, 실패하면 접촉 또는 경로 차단 근거가 있는 볼트·너트를 임시 제거한 상태를 검사한다. 통과하면 체결부 전체와 일반 부품을 하나의 묶음으로 순서에 넣는다. 이미 검사한 동일 잔여 상태와 실패 근거는 재사용한다.
3. 볼트·너트 이동 경로는 검사하지 않는다. 가장 큰 원통면의 축에서 대상 일반 부품 중심으로부터 멀어지는 부호를 선택하고, 동일 점수면 노출도가 높은 부호를 쓴다. 원통축을 얻지 못하면 6축 노출도와 중심 이격 방향을 대체 힌트로 사용하고 내부 근거에 남긴다. 고아 체결부는 기준 부품에서 멀어지는 방향으로 배치한다. UI 단계 카드에 미검증 경고는 표시하지 않는다. 내부 결과는 `NOT_TESTED`, 단계는 `FASTENER_ASSIGNED`이며 PASS가 아니다.
4. 제한된 대안·되돌아가기 후 해결하지 못한 일반 부품도 전체 편집용 초안에 넣는다. 해당 단계는 `DRAFT_UNRESOLVED`/`NOT_TESTED`, UI에는 경로 확인 필요로 표시한다. 취소는 전체 초안 자동 보충을 중단한다. 초안 전체 포함 여부와 모든 경로 검증 여부를 별도 계측한다.
5. LV CONT 사용자 지정 예외는 분해 선두, 노출도 1순위 방향이며 이후 장애물·지지 대상에서 제외한다. 기준 부품은 계속 고정 장애물이다.
6. 카메라 초점은 기준 부품 경계 중심, 거리는 최초 조립 배치 전체를 기준으로 한 고정값이다. 이동 부품·가시 부품 집합으로 매 프레임 화면 맞춤을 하지 않는다. 회전은 같은 중심·거리에서 유지한다.
7. 이동 전 2초간 하이라이트를 초당 2회 켰다 끈다. 부품은 계속 보인다. 이동 중 하이라이트를 유지하고 안착 후 해제한다.
8. 새 단계의 자재정보는 품명, 주의사항은 빈 문자열로 생성한다. 확정 시 자동 주의사항을 삽입하지 않는다. 사용자 입력 주의사항은 자동 요약·대체하지 않는다. 빈 내용에도 자재정보·주의사항 패널의 제목·테두리·배경을 그린다.
9. 실제 프로젝트 재열기 검증에서 발견한 UI/VTK 스레드 접근 오류를 수정했다. 작업 완료·진행·실패·취소를 명시적 UI 슬롯으로 전달하고 모델 표시도 UI 스레드에서 수행한다. QtWidgets DLL 배포 수정은 유지한다.

예비 실행 보완: 가상 초안은 전체 순서 생성 예산의 최대 35%까지만 사용한다. 나머지 예산은 실제 상태 검사와 체결부 삽입에 남긴다. 정지한 같은 장애물에 대한 BLOCKED는 방향이 같고 이전·현재 거리 모두 그 장애물의 전체 투영 범위를 오차 여유와 함께 벗어나는 경우 재사용한다. 다른 부품 제거로 전체 이탈 거리만 바뀌어도 같은 장애물과 충돌하는 구간을 두 경로가 모두 포함하기 때문이다. 가상 상태의 차단 근거도 이 조건으로 실제 상태에서 재사용한다. 장애물이 제거되었거나 짧은 경로이거나 UNKNOWN이면 이 조건으로 재사용하지 않는다. 재사용 기록은 현재 거리·상태와 원본 거리·상태를 함께 보존하고 계산시간은 0으로 집계한다.

수치 간섭 허용 기준과 계산용 형상 보정 v2 기준은 변경하지 않는다. 제공 자료와 기존 PILOT Studio는 수정하지 않는다.

검증·실행 결과는 `END_TO_END_V14_RESULT.md`와 `runtime-data/native-validation`의 v14 산출물에 기록한다.

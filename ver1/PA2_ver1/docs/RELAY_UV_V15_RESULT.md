# 릴레이 BSpline 분할 수정 및 한정 경로 검증

2026-10-19. 소스 수정 후 릴레이 두 개의 기존 +Z 미판정 경로만 재검사했다. 전체 순서 생성, 지지 검증, 영상 생성, EXE 재빌드는 하지 않았다. v14 프로젝트·순서·영상·배포 EXE는 기존 결과 그대로다.

## 결과

| 부품 | 기존 설정(후보 180초) | 진단용 후보 한도 360초 | 경로 계산시간 | 정밀 교차 호출 |
|---|---|---|---:|---:|
| RLY-KET400 #1 | UNKNOWN, BREP_COMMON 중 시간 초과 | PASS / CERTIFIED_CLEAR | 196.03485초 | 1,530 |
| RLY-KET400 #2 | UNKNOWN, BREP_COMMON 중 시간 초과 | PASS / CERTIFIED_CLEAR | 196.39729초 | 1,542 |

두 경로의 BSpline 형상 생성 문제는 해소됐다. 그러나 새 작업 프로세스에서 실행한 기본 180초 제한 검사는 여전히 시간 초과다. 위 PASS는 진단 호출의 시간 한도만 늘려 계산을 완료한 결과이며, 프로그램 기본 설정을 늘렸다는 뜻이 아니다. 현 설정의 전체 계획에서 자동으로 채택되는지는 별도 실행 전에는 확정할 수 없다. 확장 진단 중 일부 회귀시험을 병행했으므로 시간 수치는 격리 성능 벤치마크가 아니다.

## 동일하게 재현한 조건

- 입력: `runtime-data/end-to-end-v14-cache-final`의 관리 BREP와 v14 기록.
- 최장 채택 분해열 31단계 뒤, 관련 체결부 `NUT-FLGM5A #3`를 임시 제거했던 마지막 기록 상태를 복원했다. 다른 미해결 일반 부품을 임의로 제거하지 않았다.
- 잔여 33그룹: 검사 대상 1개와 본체를 포함한 장애물 32개. 각 릴레이 검사에는 다른 릴레이도 남아 있다.
- 상태 해시: `f8a66782e8e9d1808d027d2bc651dc8f9012a17c427f12eed319a88c9c4e160c`. 이전 검사와 새 결과의 일치를 코드에서 확인했다.
- 방향 `(0, 0, 1)`, 이동 거리 `140.82057715680867mm`.
- LV CONT는 기존 예외 정책과 제거열을 그대로 반영해 장애물에서 제외했다. 릴레이에는 예외를 부여하지 않았다.
- 간섭 거리 허용값 `0.001mm`, 최소 구간 `0.001mm`, 체적 판정 임계값 `epsilon³`, 초기 겹침 감소 허용 정책, 입력 보정 허용 기준 모두 유지했다.
- 후보 제한은 기본 검증 180초, 추가 진단에서만 360초다. 개별 네이티브 연산 제한은 모두 120초로 유지했다.
- PASS 두 건 모두 `pair_diagnostics=[]`, 초기 겹침 예외 사용 내역 없음, `CERTIFIED_CLEAR`다. 두 결과의 부품 쌍 계산은 각각 4회이며 쌍 캐시 적중은 0회다.

## 수정 내용

1. BSpline 등 비원통·비원뿔 곡면의 U 매개변수에 라디안 간격을 적용하지 않는다. 전체 U 범위를 비율로 4등분하고 기존 V 4등분과 조합해 4×4개 보수적 영역으로 검사한다. 매개변수의 수치적 크기가 커져도 분할 수가 폭증하지 않는다.
2. 분할 상한은 경계점 개수의 곱이 아닌 실제 조각 수 `(len(us)-1)*(len(vs)-1)`에 적용한다. 상한값 128 자체는 유지했다.
3. 무한점 OUT인데 부호 있는 체적이 음수인 검사 입체는, 체적 부호만 보고 뒤집어서 정확한 이동 입체로 취급하지 않는다. 기존의 보수적 대체 경로를 유지하고 `BREP_SWEEP_ORIENTATION_UNRESOLVED` 활동 기록을 추가했다. 이번에는 정상 분할된 영역으로 그 경로를 완료할 수 있다.
4. 분할 영역이 장애물과 겹치면 여전히 무간섭으로 확정하지 않는다. 기존 정밀 교차·연속 경로 판정이 그대로 적용된다.
5. 변경된 검사 결과를 이전 결과와 구분하도록 경로 정책 버전을 `path-v15-normalized-uv-conservative-sweep`로 변경했다.

두 릴레이 모두 준비된 형상의 22번·1378번 면에서 각 16개 검사 영역 생성에 성공했다. 네 면 모두 원본 입력 보정 후 유효했고, 생성된 대체 영역은 `exact=False`다. 불명확한 입체를 유효하다고 강제 승인하거나 원본 CAD를 변경한 것은 아니다.

## 검증 및 보존

- 곡면 경로, 매개변수 재표현, 모호한 방향 판정의 대체 처리, 중간의 얇은 장애물, 초기 겹침 감소, 계획 및 네이티브 격리를 포함한 회귀시험: **63개 통과, 23.38초**.
- 처음 확장 시험에서는 기본 샌드박스 데이터 경로로 BREP를 저장하다 네이티브 접근 위반이 발생했다. 해당 시험만 별도 실행해도 재현됐다. `PA2_DATA_ROOT`를 프로젝트 내부 시험 전용 경로로 지정한 최종 시험에서는 동일 시험을 포함해 63개가 통과했다. 이번 변경의 실제 릴레이 진단은 처음부터 프로젝트 내부 전용 작업 경로를 사용했다. 기본 샌드박스 저장 실패의 하위 원인은 이번 범위에서 수정하지 않았다.
- 기본·확장 진단 각각 관리 BREP 전체, v14 입력 보고서·비교 보고서, 프로젝트 DB의 실행 전후 SHA-256 일치를 확인했다. 제공 원본은 읽기/수정 대상으로 사용하지 않았다.
- 재현 도구: `tools/verify_relay_uv_sweep.py`.
- 기본 제한 결과: `runtime-data/native-validation/relay-uv-v15.json` 및 `.log`.
- 확장 진단 결과: `runtime-data/native-validation/relay-uv-v15-extended.json` 및 `.log`.
- 최종 시험 로그: `runtime-data/native-validation/tests-relay-uv-v15-workspace.log`.

소스 적용 범위는 `src/pa2/cad/sweep.py`와 `src/pa2/cad/path_check.py`의 정책 버전이다. EXE와 기존 영상에는 이 변경을 아직 재빌드·재생성하여 반영하지 않았다.

# PA² — Pilot Assembly Assistant

최신 사내 배포본은 **ver1_05**이며 `releases/PA2_ver1_05_windows_x64.zip`입니다. PLT 자동 그룹화, 미매칭 전용 기준 완화, 기준 부품의 첫 단계 표시, 시점별 공통 회전, 첫 조립 단계 기준 가로 정렬 시작, 기준 카드 이후 일반 카드 선택 버그 수정을 포함합니다. [ver1_05 변경 내용과 제한](docs/RELEASE_VER1_05.md)을 먼저 확인하세요. 아래의 v31 이전 검증 결과 및 이전 ZIP 안내는 당시 기록입니다.

PA²는 완제품 STEP을 읽어 이동 그룹을 구성하고, 보수적인 분해 경로 탐색 결과를 역순으로 조립 계획으로 만든 뒤 편집·확정하여 MP4로 출력하는 Windows 로컬 프로그램입니다.

현재 구현은 실행 가능한 검증 버전입니다. 2026-10-18 수정으로 접촉·방향·경로의 정밀 CAD 계산을 별도 프로세스로 격리했고, 32그룹 상한을 제거했습니다. 제공된 176솔리드/65그룹 모델의 243개 근접 후보를 모두 판정해 접촉 121개, 미판정 0개를 확인했습니다. 이제 이 모델도 순서 탐색을 시작합니다. 전체 순서 확정 가능 여부는 경로 간섭·초기 관통·지지 판정 결과에 따라 달라집니다. 자세한 범위는 [구현 및 검수 상태](docs/IMPLEMENTATION_STATUS.md)를 확인하세요.

[정책](docs/RECOGNITION_V22.md), [인식 확인 결과](docs/RECOGNITION_V22_RESULT.md). 순서·간섭·학습·영상은 이번에 실행하지 않았고 ZIP도 갱신하지 않았습니다.

v21: 순서·6축 방향용 LGBMRanker를 같은 데이터 기준으로 순차 학습하는 공통 주기, 유휴 실행·자원 한도·중단/재개, 실제 CAD 비교와 조합별 적용 판정, 모델 쌍 관리·이전 모델 복원을 구현했습니다. **사용자 요청으로 학습 실행·학습 성능 검증은 하지 않았습니다. 자동 학습·자동 적용은 기본 꺼짐이며 더미 프로젝트가 준비된 다음 별도 검증합니다.** [구현 범위와 이후 검증 항목](docs/LEARNING_LIFECYCLE_V21.md), [작업 결과](docs/V21_IMPLEMENTATION_RESULT.md)를 확인하세요. ZIP은 갱신하지 않습니다.

아래는 기존 v20 구현·실측 기록입니다. STEP 부품 대표색, 빨간 선택/영상 하이라이트, 단일 선택 시 주변 회색·불투명도 25%, **자동생성 옆 수동생성**, 최초 초안 보존·편집값 자동 저장, 확정 데이터 자동 수집과 유사도 지표를 지원합니다. 수동생성은 일반 부품을 목록 순서/분해 +Z 기본값으로 배치하고 기존 연결 정보로 체결부를 삽입하며, 간섭 검사는 하지 않습니다. 상단 **학습 현황**에서 수집량과 원본 비교를 확인합니다.

```powershell

```

```powershell

```

## 사용 흐름

1. `프로젝트` 화면에서 프로젝트명·차종·품종을 입력하고 완제품 STEP과 선택적 부품 STEP을 고릅니다.
2. 분석 후 `모델·순서` 화면에서 기준 부품을 선택하고 `자동생성` 또는 `수동생성`을 누릅니다. 수동생성은 경로 검사 없이 빠르게 편집용 초안을 만듭니다.
3. 순서 카드의 방향·거리·카메라·문구를 편집합니다. 작업 속성의 `미리보기`로 선택 단계를 재생하고, `선택 단계에 적용`으로 편집을 반영합니다. `미리보기 갱신`은 전체 편집본의 조립 완료 장면을 표시합니다.
4. v14는 미해결 일반 부품도 편집용 단계로 포함합니다. `경로 확인 필요` 카드를 확인하고 편집한 뒤 확정합니다. 전체 계획은 모든 이동 그룹의 일치 여부를 검사합니다. 이전 부분 결과도 부분 확정·영상화할 수 있습니다.
5. `영상` 화면에서 1920×1080, 30fps H.264/yuv420p MP4를 만들고 별도 경로로 내보냅니다.

프로젝트 목록을 더블클릭하면 관리 사본과 BREP 캐시에서 재열며 외부 STEP을 다시 파싱하지 않습니다. 새 색상 캐시가 없는 구버전 프로젝트는 최초 한 번 관리 STEP에서 캐시를 재생성합니다. 프로젝트 삭제는 soft-delete이며 외부 원본, 공용 자산, 독립 학습 사례를 삭제하지 않습니다.

최신 수정은 정밀 형상 유효성을 보존하기 위해 캐시와 계산 프로세스 전달을 바이너리 BREP로 변경했습니다. 기존 프로젝트를 처음 다시 열 때는 앱이 보관한 STEP 사본으로 새 캐시를 한 번 생성하므로 시간이 걸릴 수 있습니다. 외부 참고자료와 기존 캐시는 수정하지 않습니다.

이전 버전에서 접촉 그래프가 미완료였던 프로젝트도 다시 등록할 필요 없이 열고 `자동생성`을 누르면 접촉 계산을 갱신합니다. 수동생성은 접촉 계산도 갱신하지 않고 저장된 정보를 재사용합니다. 작업 중 `작업 취소`는 계산 프로세스에 전달되며, 응답 없는 계산은 5초 이내 강제 종료합니다. 단일 CAD 호출 기본 120초, 방향 후보 기본 240초, 순서 탐색 기본 3600초가 적용됩니다. 취소한 탐색은 기존 초안·확정본을 덮어쓰지 않습니다.

사용자 요청으로 **모든 부품의 초기 겹침 감소 예외**와 지지 미확인 단계의 검토용 초안을 기본 활성화했습니다. 설정 → 형상 판정·탐색에서 끌 수 있습니다. 처음부터 겹친 쌍만 최대 0.5 mm 간격으로 부피를 검사하며, 누적 최저값 대비 재증가는 차단합니다. 분리 후 남은 경로와 처음 겹치지 않은 다른 상대는 연속 검사합니다. 종점은 원래 형상과 분리되어야 합니다. **검사 위치 사이의 재증가와 같은 상대 내 국소 새 간섭은 배제하지 못하므로**, 예외 단계에 경고를 남기고 계획은 `REVIEW_REQUIRED`로 저장합니다. 감소 예외를 끄면 [이전 고정 초기 영역 정책](docs/INITIAL_REGION_POLICY.md)이 적용됩니다. 전체 부품 예외를 끄면 별도 볼트 축 방향 예외가 적용되며, 엄격한 초기 겹침 차단은 전체 부품 예외와 볼트 예외를 모두 꺼야 합니다. 부분 확정은 완성 계획이나 학습 정답으로 취급하지 않습니다.

v14 기본 알고리즘의 볼트·너트 경로 검사 생략은 위 초기 겹침 스위치와 별도의 요청 정책입니다. 초기 겹침 스위치를 꺼도 볼트·너트 경로 검사를 재개하지 않습니다. 영상 주의사항에 자동 경고를 넣지 않으며, 기하 판정 근거는 단계 상태와 진단에 보존합니다.

## 데이터 위치와 원본 보호

기본 데이터 루트는 `%LOCALAPPDATA%\THN\PA2`입니다. 개발·시험에서는 `PA2_DATA_ROOT` 환경 변수로 별도 위치를 지정할 수 있습니다.

```text
projects/   프로젝트 소유 영상 등
assets/     SHA-256 기반 불변 관리 사본
cache/      완료 표식이 있는 단계별 공용 캐시
jobs/       작업 임시 영역
learning/   프로젝트 삭제와 독립된 학습 자료
database/   개발 SQLite DB 또는 전용 MariaDB 데이터
logs/       진단 로그
```

외부 입력은 읽기 전용으로 취급합니다. 관리 사본은 복사 후 SHA-256을 재검증하고, 캐시와 영상은 임시 파일을 완성한 후 원자적으로 공개합니다. 참고자료 24개는 [해시 manifest](docs/reference_hashes.json)와 `tools/verify_reference_integrity.py`로 검증할 수 있습니다.

## 테스트

```powershell
PowerShell -ExecutionPolicy Bypass -File .\scripts\test.ps1
```

현재 자동 시험은 파일명 분류, 그룹 분할, 얇은 장애물, 보수적 UNKNOWN, 지지, 역산, 편집 형식, 캐시, 저장소, 학습 행, VTK 오프스크린 렌더링과 실제 H.264 MP4 인코딩을 포함합니다.

## 배포 빌드

```powershell
PowerShell -ExecutionPolicy Bypass -File .\scripts\build.ps1
```

빌드는 `build\distribution\PA2`에서 패키징을 마친 뒤 프로젝트 루트인 `PA2_ver1` 바로 아래에 `PA2.exe`와 `_internal`을 배치합니다. 기존 실행 파일과 의존 파일은 `build\previous-release-*`에 보존합니다. `PA2.exe`와 `_internal`을 함께 배포합니다. `packaging\installer.iss`는 이 두 항목만 설치하는 Inno Setup 입력입니다. 완전한 오프라인 설치 검수에는 MariaDB 전용 런타임 묶음과 Inno Setup 컴파일러를 빌드 PC에 추가해야 합니다. 현재 개발 실행은 SQLAlchemy SQLite fallback을 사용하고 `PA2_DATABASE_URL`이 설정되면 MariaDB/PyMySQL 연결을 사용합니다.
